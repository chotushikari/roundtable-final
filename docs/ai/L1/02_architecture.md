# Architecture

The public `/` route is separate from the candidate invitation surface. `RoundTableExperience` owns a three-scene, requestAnimationFrame-interpolated Three.js artifact with DOM-measured layout anchors and projected role badges. All three content sections crossfade on one shared stage while the same artifact interpolates between them, using frame-rate-independent easing and normalized wheel input. Navigation stops at scene three and pauses during voice activity; narrow screens stack and scroll scene content vertically. `InteractiveInterviewMock` now wraps a real one-question sample in an interview-room-style shell with a conversation guidance rail and explicitly descriptive role previews, not simulated live controls. `LandingPage` exposes interview and companion demo variants reusing the existing Agora RTC/RTM lifecycle and reports activity to the presentation shell. There is no browser TTS fallback, fabricated transcript, or hardcoded live metric. The start boundary selects only server-owned modes: a one-question interview with a 20-second idle timeout or a fixed companion greeting with a 15-second idle timeout. Both auto-stop after their bounded response. They are development-enabled and require `ENABLE_HOMEPAGE_VOICE_DEMO=true` in production. Neither creates assessment evidence.

Workspace selection uses required questions and published scenarios through `workspace-policy.ts`. The candidate's polled `workspacePrompt` explains the task; code/canvas modality expands a persistent workspace with compact transcript/visualizer and available audio controls. Canvas is one embedded Excalidraw surface for shapes, arrows, text, and freehand drawing; scenes are capped at 500 KB. Voice workspace commands execute through the Agora custom LLM route without consuming a scored panel answer. “Now see it,” “check now,” “check no,” “review my code,” “can you see it?”, and “updated” inspect the requested latest autosave without executing candidate code. Language-choice and hint requests receive short task-specific help without scoring or advancing the panel. Code review checks the requested function and core logic, including compact task-specific implementations; canvas review checks saved text labels and arrows, explicitly reports a blank canvas, and never falls back to code content. A complete code task or Client/API Server/Database canvas diagram with at least two arrows gives grounded feedback and automatically advances the demo panel. Evaluator input remains limited to deliberate checkpoints; autosaved snapshots are used only for on-demand candidate voice review. Draft/checkpoint audit events are distinct; the artifact PUT accepts an optional `checkpoint` flag for audit labeling.

Candidate session creation returns RTC/RTM credentials immediately. The browser enters the room while `/api/sessions/:id/start` starts the managed agent with a per-session custom-LLM credential. One agent uses Agora-managed Deepgram STT and calls `/api/ai/chat/completions`; the route evaluates each substantive answer for every role, validates literal evidence, applies deterministic phase/controller rules, persists with compare-and-swap, and streams one question. `SARVAM_API_KEY` selects the authenticated `/api/ai/sarvam/tts` bridge, which fixes Sarvam Bulbul v3 `shubh` and returns 24 kHz PCM to Agora; without it the established MiniMax TTS configuration remains the startup fallback. This selection occurs at agent construction, so provider failures during an active session are surfaced rather than silently changing a candidate's voice. The browser renders a lightweight, role-aware animated avatar from the server-owned active role and Agora agent state; it is not a video stream and adds no media track. Pause and repeat utterances are transcripted control turns and do not advance evidence state.

Before the full candidate room is revealed, `ConversationComponent` shows a bounded preparation surface while RTC joins and the agent appears as a remote user. It is a client-only UI bridge: AI disclosure, microphone expectations, and evidence boundaries remain visible for at least fifteen seconds, but it exits only after both conditions are genuinely ready. A connection that remains pending is explicitly shown as setup and can be exited; it must never be represented as interview progress or a fabricated connection success.

The optional camera interaction check is candidate-initiated and consent-gated. It creates a random gesture-and-phrase challenge, records one short temporary browser clip, and sends it to Gemini through authenticated server routes. The server stores only a human-review `completed`, `inconclusive`, or `unavailable` event; it stores no clip, does not publish it to Realtime, and does not feed it into controller evidence or the final assessment. It is a live-interaction signal only, never identity, voice-authenticity, or deception detection.

The company dashboard creates job-scoped interview definitions from role context and desired outcomes. Its builder supports a fixed five-role, ten-minute finale showcase or a selected two-to-five-role adaptive panel with a 5–90 minute budget; these inputs are validated by `InterviewCreateSchema`, persisted with the definition, and frozen in the published version. When a job has a complete (three or more competencies) weighted hiring bar, plan generation loads it server-side and freezes those exact competency keys, descriptions, and normalized weights into the generated plan before publication. Generated question wording may adapt, but it cannot replace the recruiter-owned rubric. The authenticated custom-LLM route handles interview controls and workspace review commands without exposing an external issue-tracker workflow to candidates.

Explicit demo mode is a strict, judge-friendly sequence: Hiring Manager, Technical, Product, Customer, then Behavioural. Each substantive answer is evaluated for every role, and evidence changes the next role's question but never the role order. Five answers trigger a closing statement; the browser finalizes after its completed transcript and idle/listening agent state. A fixed fifteen-second preparation screen runs before the managed agent and candidate microphone start, so the demo's ten-minute deadline begins afterwards. The first audible panel turn is the opening interview question rather than a generic invitation greeting. Candidate polling exposes only a plain-language Panel focus explanation—not scores or private evaluation—so the handoff is understandable. Pause/repeat/readiness requests do not advance it. New ten-minute dashboard demos assign code to Technical and canvas to Product. Older invitations retain their duration and sequence; normal interviews use full adaptive priorities.

Demo end-of-speech waits 1500 ms. `lib/demo-turns.ts` groups answer fragments by the server-owned pending question and reserves one accepted answer for that question. Candidate-only polling includes the pending question ID/text. The browser acknowledges `QUESTION_DELIVERED` after matching a completed agent transcript and observing idle/listening/silent state. The authenticated event endpoint checks that receipt against the current question; roles and scores remain server-owned. An undelivered question is repeated; partial sentences stay pending. “Please continue,” “next question,” and completed workspace reviews write dedicated navigation events and advance the panel without creating candidate transcript evidence or assessment findings. Durable private session events hold receipts, fragment text, workspace handoffs, and cached responses under the existing retention policy. Local memory turn reservation is synchronous to match the database's atomic uniqueness guarantee.

Supabase is the production store and Google-only interviewer auth provider. Each authenticated interviewer is assigned an idempotent personal organization whose UUID matches the auth user UUID; definitions, invitations, private resume objects, sessions, and reports inherit that organization ID. Candidates remain unauthenticated guests behind signed single-use invitations. The additive Hiring Graph introduces Jobs, Job Competencies, Candidates, Job Candidates, Integrity Events, Human Decisions, Audit Logs, and Notifications. Existing interview definitions and versions remain the compatibility-preserving Blueprint and Blueprint Version records, and nullable job/candidate bridges ensure the running interview pipeline is unchanged until its APIs are deliberately migrated. An in-memory adapter is development/test-only and is prohibited in production. E2B is called only by the server-selected workspace harness. Test packs are selected from the pending coding question and run against autosaved Python, JavaScript, or TypeScript source: `reverseString` and even-number tasks have functional cases; unknown tasks receive syntax/runtime validation. Changes from `company_session_status` are broadcast to a private organization topic; no content table is added to the Realtime publication.

When a candidate ends the interview, finalization reconciles durable turns, analyses, workspace-completion events, and immutable artifact versions before persisting the assessment and marking the session completed. Each accepted answer is associated with the interviewer turn immediately before it; because Agora speaks the opening before durable interviewer history begins, the first accepted demo answer belongs to Hiring Manager. Navigation and workspace-control utterances never become evidence. Completed code and canvas tasks can produce conservative rubric evidence backed by an `artifact_versions.id`; incomplete or skipped workspaces do not. Structural workspace evidence never claims exhaustive runtime correctness, and duplicate artifact evidence is not repeated as multiple headline strengths. `GET /api/sessions/:id/report` is a company-authenticated, post-completion projection for the dashboard. It combines the immutable interview version, invitation metadata, final assessment, transcript evidence links, coverage, and factual workspace summaries. Transcript evidence opens its cited turn and artifact evidence opens the Workspace section. It never uses the live company Realtime channel and does not expose controller cache, raw media, or raw workspace source in the report projection.
